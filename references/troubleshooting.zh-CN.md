# 故障排除

连接设置见[连接配置](configuration.zh-CN.md)，准确参数见[命令参考](commands.zh-CN.md)。本文示例从项目根目录运行。JSON 模式下检查退出码和解码后的错误对象，人类诊断信息在 stderr。

## 连接与时区

| 现象 | 处理方式 |
|---|---|
| 设备码报告找不到应用 | 自带应用时检查 Client ID、支持的账户类型和公共客户端设置，见 [Azure 配置](azure-app-setup.zh-CN.md)。 |
| 登录过期、`invalid_grant` 或认证失败 | 重新运行 `python scripts/outlook_setup.py`。 |
| 403 权限错误 | 检查 `Calendars.ReadWrite`；读取邮箱时区还需要 `MailboxSettings.Read`。 |
| 时间偏差数小时 | 查看 `context --json` 与 `status --json`，显式传入预期的命名 `--timezone`。缺少时区数据时用同一个 Python 解释器安装 `tzdata`。 |
| 显式时区被拒绝 | 使用有效 IANA 或当前 Windows 名称，如 `Asia/Shanghai`、`China Standard Time`；UTC 偏移不是时区名称。 |
| 全天日程显示为跨两天 | 检查邮箱时区访问权限，重新连接授予 `MailboxSettings.Read`；可用时全天写入采用邮箱时区。 |
| 夏令时切换导致本地时间不存在 | 写入会被拒绝。根据用户意图选择实际存在的本地时间，后端不会让服务端静默调整。 |
| 夏令时切换导致本地时间有歧义 | 写入会被拒绝。先明确用户指该墙钟时刻的哪一次，换算实际 UTC 时刻，再用 `--timezone UTC` 传入明确的开始与结束。 |
| 空闲查询跨越偏移跳变，或端点不存在/有歧义 | 用 `--timezone UTC` 查询实际 UTC 区间；`HH:MM` 时段无法区分重复的本地时刻。不经过跳变的普通窗口仍可使用。 |

## 输入与查询错误

| 输入 / 现象 | 修正方式 |
|---|---|
| 日期参数使用 `本周五`、`2026/09/11`、缺少补零、秒或时区后缀 | 模型先解析语言，再根据参数要求严格传 `YYYY-MM-DD`、`YYYY-MM-DD HH:MM` 或 `YYYY-MM-DDTHH:MM`，时区单独提供。 |
| 创建时段日程省略结束，或开始只有日期 | 明确提供开始和结束；仅在用户需要全天日程时使用 `--all-day`。 |
| 类型转换只给一个边界 | 时段/全天转换必须同时给 `--start` 和 `--end`。 |
| 结束早于或等于开始 | 修正最终区间；全天日程的 CLI 结束日期包含当天。 |
| `list` 缺少查询基准，或混用发生日期和创建日期 | `--from` 与 `--created-after` 必须恰好给一个；`--created-before` 仅与后者搭配，且上界日期必须更晚。 |
| 创建筛选查到安排在其他日期的日程 | 创建时间与发生时间是不同字段；查询何时发生应使用 `--from`。 |
| 重复 JSON 无效，或字段/类型不支持 | 使用[定期日程](recurring-events.zh-CN.md)规定的结构，优先 `--repeat-file` 避开 shell 引号问题。 |
| `--repeat-times 0` 或截止早于开始 | 次数使用正整数；截止用不早于日程开始的绝对日期；最多给一个结束条件。 |
| 结束条件/次数没配规则 | 同时给 `--repeat` 或 `--repeat-file` 及所需结束条件。 |
| 提醒为负数，或全天提醒超过 1826 天 | 使用非负值，并遵守全天上限；时段提醒的单位是分钟。 |
| ID 为空/不存在、同时给两个移动选项或移动零天 | 使用结果返回的 ID；`--days` 与 `--to` 恰好选一个，实际移动不能为零。 |

## 日程操作

| 现象 | 处理方式 |
|---|---|
| 已删除的某次定期日程报告不存在 | 查询明确日期窗口验证缺席，不复用已删除的单次 ID。 |
| 移动某次跨越了相邻出现 | 选择 Graph 允许的相邻出现边界内的目标时间。 |
| 修改系列规则后，之前的例外变化了 | 修改系列规则可能重置例外；执行前明确该影响与用户要求的范围。 |
| 更新规则后原结束条件消失 | 提供新规则会重建 range，省略两个结束选项表示无截止。需要保留原条件时先读取，再明确传入截止或次数。 |
| 结果缺少已有日程 | 检查账户、命名时区、准确窗口和筛选条件。按发生日期查询会展开单次出现，按创建日期查询使用另一个端点。 |
| 添加时没有冲突提示 | `--force` 会跳过检查；空闲或已取消的日程不算占用。 |
| 创建/更新请求超时 | 结果可能未知；重新提交相同的规范化请求前，先检查服务端目标日程状态。 |

## 异常失败与不支持的功能

Python traceback 属于非预期情况，应记录去除敏感信息后的命令、脚本路径和错误，供排查。常规结构化错误应能说明无效输入或 Graph 失败。

六种 Graph 规则不支持按小时重复或按工作日数量计算间隔。工具也不导入 `.ics` 文件，不提供多个日历之间的选择；它操作当前连接账户的默认日历，重新连接可切换账户。
