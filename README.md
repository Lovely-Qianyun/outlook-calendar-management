# Outlook 日历助手

一个让 AI 助手通过对话帮你管理 Outlook 日历（微软账户 / outlook.com）的工具包。你只要说一句“周五下午两点到五点有空吗？”或“把周会改到周三”，AI 就会自动帮你完成查看、添加、修改、移动、删除日程等操作，支持定期日程（比如每周重复的例会）和空闲时段查询。全程不用打开 Outlook 应用，手机、电脑、网页上的日历实时同步。

## 这个项目是给谁用的

本项目的定位是**给 Agent 用的 skill**：`SKILL.md` 是 agent 读取的操作手册，这份 `README.md` 是给人看的项目首页。

第一次接触技能，需要了解以下概念：

- **Agent（智能体）**：能自己调用工具干活的 AI 助手，比如 Claude Code、Hermes 等智能助手
- **Skill（技能）**：给 Agent 用的“说明书 + 工具包”。本质是一个目录，里面写着“这个工具能干什么、怎么用、什么情况下用”，Agent 读到就能学会用它
- **定期日程**：会按规则自动重复的日程，比如“每周一 9 点的周会”，创建一次，按规则自动延续
- **输出协议**：程序输出格式的固定约定（详见“工作原理”），保证 AI 和脚本永远不会读错结果

## 特性

- 全量日程操作：查看、按标题/地点/类别查找、添加、修改、移动、删除
- 定期日程：创建、改单次、改整系列规则、删整系列、查下次出现
- 空闲时段查询：问“周五下午几点有空”直接给答案
- 中英双语输出，按系统语言自动选择，`--lang zh|en` 或环境变量 `OCAL_LANG` 覆盖
- 首次运行自动安装依赖（含时区数据 `tzdata`，保证 Windows 上时间解析正确），不用手动装
- 机器可读：任意命令加 `--json`，输出就是干净的 JSON 数据，方便其他程序直接使用
- 结果稳定可解析：事件 ID 用 🆔 固定标记（见“工作原理”），AI 和脚本总能可靠地找到它

## 快速开始

把整个项目目录放进你的 Agent 的 `skills` 目录（Hermes、Claude Code 等平台的技能目录），Agent 就能帮你管日历了；也可以直接在终端里手动运行：

```bash
# 第一次使用：登录认证。终端会显示一个验证码，
# 浏览器打开 microsoft.com/link 输入它即可完成授权
python scripts/outlook_setup.py

# 查看未来 7 天的日程
python scripts/outlook_cal.py list --days 7

# 添加一条日程：标题、开始时间、结束时间，可选提前提醒（分钟）
python scripts/outlook_cal.py add "周会" "2026-08-10 09:00" "2026-08-10 10:00" --remind 10
```

依赖 requests、msal、tzdata 会在首次运行时自动安装，不用手动装。认证一次后自动续期，登录信息存在用户主目录的 `~/.outlook_cal_token.json`。

## 使用示例

```
$ python scripts/outlook_cal.py list --days 3
📅 08月10日 周一
    🕐 08/10 09:00 - 08/10 10:00  周会 🔁每周一 [工作]
    🆔 AAMkAD...

$ python scripts/outlook_cal.py free "2026-08-14" --from 09:00 --to 18:00
📅 08月14日 周五：09:00-10:00、14:00-18:00 空闲

$ python scripts/outlook_cal.py delete <ID> -y
🗑️ 已从日历中移除本次出现「周会」（其余出现保留）
```

命令输出里的 🆔 行就是这条日程的 ID，所有修改、删除、移动操作都从它取。

## 工作原理

总的设计思路只有一条：**输出永远可预测、可验证**，机器不会读错，人也不会看不懂。下面三条是它的支柱：

- **走微软官方接口，和手动操作等价**：程序调用 Microsoft Graph API，一个微软为 Outlook 日历提供的官方接口，与你自己在 Outlook 里操作的效果完全一致，改动实时同步到手机、电脑、网页。登录采用"设备码"方式：首次运行会得到一个验证码，浏览器打开 microsoft.com/link 输入它即可，之后由微软的登录库（Microsoft Authentication Library，MSAL）自动续期。**没有本地服务常驻后台**。
- **时区按你的电脑自动处理**：所有时间按电脑本地时区解析、显示和换算（Windows 时区名自动映射），跨时区也不用自己算。
- **输出遵循固定"协议"，机器不会读错**：命令的输出格式是固定的——每条日程的 ID 永远出现在以 🆔 开头的那一行（示例里的 `AAMkAD...`），时间、地点、类别等也都有固定的格式和标记。这些标记（emoji 锚点）与语言无关，中文、英文输出用的是同一套，所以 AI 和脚本在任何语言环境下都能稳定解析。需要程序化使用时，加 `--json` 即可得到纯净的 JSON 数据，里面没有任何提示性文字。

## 目录结构

```
outlook-calendar-management/
├── SKILL.md            # Agent 的操作手册（触发条件 + 使用规则）
├── DEVELOPMENT.md      # 开发者文档：输出协议、设计决策、测试方法
├── scripts/            # 全部实现（纯 Python，无框架）
├── tests/              # 单元测试 + 触发评估集 + 可选实机演练
└── references/         # 用户文档：命令参考、定期日程、配置、排障
```

## 测试

- **202 个离线单元测试**（pytest）：按功能模块覆盖，网络请求全部模拟（不联网、不需要真实账户），随时可跑
- **触发评估集**（`tests/trigger-eval.md`）：一整套"哪些话该触发这个 skill、哪些话不该触发"的样例。改动 SKILL.md 里的触发描述时用它对照检查，防止漏触发和误触发
- **可选实机演练**：用真实 Outlook 账户跑 64 项检查，验证与真实服务的兼容性（需要专用测试账户，见 `tests/integration/`）

## 开发

想参与开发，先读 `DEVELOPMENT.md`——里面有完整的输出协议、关键设计决策、多语言（i18n）约定和 Graph API 官方文档链接。

核心原则：

- **输出协议不能破坏**：输出格式是用户和脚本依赖的契约，改动要极其慎重
- **中文输出保持逐字稳定**：文案被测试逐字钉住，改动需同步更新测试断言并升版本号，不随意改
- **改行为先跑回归测试**：任何行为变化，先跑一遍全部测试，确认没改坏任何东西
