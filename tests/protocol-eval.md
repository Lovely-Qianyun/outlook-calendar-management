# 输出协议评估集

验证 agent 和脚本能从命令输出中**稳定、无误地**提取关键信息。改输出格式前后各跑一遍，防止协议被破坏。

自动化的部分在 `tests/test_protocol.py`（同样的正则逐条钉住）；本文件是给人/agent 对照用的评估集，用于新会话里的端到端验证。

## 提取正则（协议承诺，不得变）

| 信息 | 正则 | 说明 |
|------|------|------|
| list 的 🆔 | `^    🆔 (.+)$` | 4 空格缩进 |
| add 的 🆔 | `^   🆔 (.+)$` | 3 空格缩进 |
| read 的 🆔 | `^🆔 (.+)$` | 顶格 |
| 系列主事件 ID | `^🆕 系列主事件ID: (.+)$` | 顶格 |
| free 时段 | `(\d{2}:\d{2})-(\d{2}:\d{2})` | 逐段 HH:MM-HH:MM |
| --json 错误 | `{"error": ..., "exit": 1}` | stdout 可 json.loads |

## 硬规则（违规即协议破坏）

1. **🆔 行是事件 ID 的唯一来源**，agent 绝不猜测或编造 ID
2. **stdout 里的 🆔 只能属于结果事件**：冲突警告等非交互提示（含现有日程的 🆔）一律在 stderr——从 stderr 提取 ID 是错误用法
3. 锚点（🆔/🆕/✅/⚠️…）与语言无关，zh/en 完全一致；`--json` 输出也与语言无关
4. `--json` 模式下 stdout 是纯净 JSON，人类提示全部在 stderr

## 评估用例

对每条用例，在全新会话里让 agent 执行操作并提取信息，核对提取结果。

| # | 操作 | 期望提取 | 常见错误 |
|---|------|---------|----------|
| 1 | `list --days 7`，输出 3 条日程 | 3 个 🆔（4 空格行），与输出一一对应 | 抓了 stderr 的内容；把时间当 ID |
| 2 | `add "周会" "2026-08-20 15:00"`（与现有日程冲突） | 新日程的 🆔（3 空格行）| 抓到冲突警告里现有日程的 🆔 |
| 3 | `read <某次出现ID>` | 该次 🆔 + 🆕 系列主事件ID 两个值 | 把系列主 ID 当成该次 ID 去删 |
| 4 | `free "2026-08-21" --from 09:00 --to 18:00` | 空闲时段列表（HH:MM-HH:MM） | 解析整天空闲/无空闲两种形态时崩溃 |
| 5 | `delete <ID> -y` 单次日程 | "已从日历中移除「标题」" + 无残留 ID | 忽略"可找回"提示行 |
| 6 | 任意命令 `--json` | stdout 直接 json.loads 成功 | 把 stderr 提示混进解析 |
| 7 | `add "坏时间"` 出错 | stderr 有 ❌；stdout 为空 | 从 stdout 找错误 |
| 8 | 英文环境（`--lang en`）跑 1-5 | 锚点与中文环境完全一致 | 按中文文案做断言 |
| 9 | 定期系列：`read` 某次 → `update <主ID> --repeat "每周三"` | 主 ID 来自 🆕 行，而不是某次 ID | 用某次 ID 改规则（会被拒绝） |
| 10 | `next <系列ID>` | 下次出现的 🆔（4 空格行） | 把"系列已结束"提示当正常输出 |
| 11 | `add "周会" "今天 14:00" "今天 15:00"`（用户说"今天下午两点"） | 输出里的日期是**当前日期**（可运行 `status` 看"当前日期"行核对），不是旧会话里的日期 | 把"今天"按旧上下文/昨天换算 |

期望标准：11/11。任何一条失败都说明输出协议被破坏，回退改动或更新本文件与 test_protocol.py。
