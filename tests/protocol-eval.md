# 输出协议评估集

用于验证 agent 与脚本能否从命令输出中**稳定、无误地**提取关键信息。每次修改输出格式前后各运行一遍，以防协议被破坏。

自动化的部分位于 `tests/test_protocol.py`（同一套正则逐条固化）；本文件是供人/agent 对照使用的评估集，用于全新会话中的端到端验证。

## 提取正则（协议承诺，不得变）

| 信息 | 正则 | 说明 |
|------|------|------|
| list 的 🆔 | `^    🆔 (.+)$` | 4 空格缩进 |
| add 的 🆔 | `^   🆔 (.+)$` | 3 空格缩进 |
| read 的 🆔 | `^🆔 (.+)$` | 顶格 |
| 系列主事件 ID | `^🆕 .+?: (.+)$` | 锚点+冒号结构，顶格；冒号前文案随语言（zh: 系列主事件ID / en: Series master event ID） |
| free 时段 | `(\d{2}:\d{2})-(\d{2}:\d{2})` | 逐段 HH:MM-HH:MM；无时段列表 = 整天空闲或无空闲（区分依赖文案或 `--json`） |
| --json 错误 | `{"error": ..., "exit": 1}` | stdout 可 json.loads |

## 硬规则（违规即协议破坏）

1. **🆔 行是事件 ID 的唯一来源**，agent 严禁猜测或编造 ID
2. **stdout 里的 🆔 只能属于结果事件**：冲突警告等非交互提示（含现有日程的 🆔）一律在 stderr——从 stderr 提取 ID 是错误用法
3. 锚点（🆔/🆕/✅/⚠️…）与**结构**（缩进/冒号/括号/时段格式）与语言无关，zh/en 完全一致；`--json` 输出也与语言无关
4. **自然语言文案不属于协议**：行内文案（如"系列主事件ID / Series master event ID"、"确认? / Confirm?"）随语言自由翻译，agent 提取信息只依赖锚点与结构，不依赖具体文案
5. `--json` 模式下 stdout 是纯净 JSON，人类提示全部在 stderr

## 评估用例

对每条用例，在全新会话里让 agent 执行操作并提取信息，核对提取结果。

| # | 操作 | 期望提取 | 常见错误 |
|---|------|---------|----------|
| 1 | `list --days 7`，输出 3 条日程 | 3 个 🆔（4 空格行），与输出一一对应 | 误抓 stderr 内容；将时间误作 ID |
| 2 | `add "周会" "2026-08-20 15:00"`（与现有日程冲突） | 新日程的 🆔（3 空格行）| 抓到冲突警告里现有日程的 🆔 |
| 3 | `read <某次出现ID>` | 该次 🆔 + 🆕 行主事件 ID（锚点+冒号结构）两个值 | 将系列主 ID 误作该次 ID 执行删除 |
| 4 | `free "2026-08-21" --from 09:00 --to 18:00` | 空闲时段列表（HH:MM-HH:MM）；无时段列表 = 整天空闲或无空闲 | 在无时段列表的形态上误判为"有空闲时段" |
| 5 | `delete <ID> -y` 单次日程 | stdout 有删除成功行（🗑️ 锚点），无残留 ID | 忽略"可找回"提示行 |
| 6 | 任意命令 `--json` | stdout 直接 json.loads 成功 | 将 stderr 提示混入解析 |
| 7 | `add "坏时间"` 出错 | stderr 有 ❌；stdout 为空 | 从 stdout 查找错误 |
| 8 | 英文环境（`--lang en`）跑 1-5 | 锚点与中文环境完全一致 | 按中文文案做断言 |
| 9 | 定期系列：`read` 某次 → `update <主ID> --repeat "每周三"` | 主 ID 来自 🆕 行，而不是某次 ID | 用某次 ID 改规则（会被拒绝） |
| 10 | `next <系列ID>` | 下次出现的 🆔（4 空格行） | 将"系列已结束"提示误作正常输出 |
| 11 | `add "周会" "今天 14:00" "今天 15:00"`（用户说"今天下午两点"） | 输出里的日期是**当前日期**（可运行 `status` 看"当前日期"行核对），不是旧会话里的日期 | 将"今天"按旧上下文/昨天换算 |

期望标准为 11/11。任一条失败即说明输出协议被破坏，应回退改动，或同步更新本文件与 test_protocol.py。
