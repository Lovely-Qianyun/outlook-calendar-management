# Skill 级评估集

评估 agent 加载本 skill 后的**实际操作质量**，而非仅验证触发与否（触发验证见 `trigger-eval.zh-CN.md`，输出协议验证见 `protocol-eval.zh-CN.md`）。

依据 Anthropic / OpenAI 的 skill 设计推荐：触发成功 ≠ 按预期操作，需在全新会话中做 with/without 基线对比。

## 使用方法

对每个场景，在**全新会话**里原样提问，分别在有 skill 和没有 skill 的情况下记录行为，按判定标准核对：

- **命令调用**：是否调用了 `outlook_cal.py` 的 CLI（而非臆测）
- **参数正确性**：时间参数是否按运行时刻解析（非旧会话日期）
- **铁律遵守**：删除前是否确认、修改前是否 read、操作后是否回读验证
- **失败处理**：出错时是否读 ❌ 行并针对性处理（不盲目重试）

## 评估场景

| # | 用户请求 | 判定标准（全部满足才算过） |
|---|---------|------------------------------|
| 1 | "看看明天有什么安排" | ① 调用了 `today`/`list`/`week` 之一；② 命令输出含当前日期解析结果（非旧会话日期）；③ 汇报时给出日程标题+时间，而非只回"已查询" |
| 2 | "把周五的会挪到下周" | ① 先 `list`/`search` 定位（拿到 🆔）再 `move`；② 移动前向用户复述目标日程或回读确认；③ `move` 后回读核对新日期；④ 未编造 ID |
| 3 | "删掉明天下午的会议" | ① 删除前向用户复述日程（标题+时间）并获同意；② 使用输出中的 🆔；③ 删除后回读/汇报实际结果；④ 若命令失败，按 ❌ 行提示处理而非原样重试 |

## 判定口径

- with/without 基线：无 skill 时 agent 可能直接臆造命令或要求用户手动操作；有 skill 时应稳定走 CLI 流程
- 铁律 1（取当前时间与时区）：场景 1 中若 agent 使用旧会话日期换算"明天"，直接判定失败
- 通过标准：3/3 场景全部满足判定标准

## 改动对照

修改 SKILL.md（铁律、常见任务、输出契约）后重跑本评估集；协议层改动（输出格式）跑 `protocol-eval.zh-CN.md`；触发描述改动跑 `trigger-eval.zh-CN.md`。
